# 电能质量告警定值一次性读取与赋值

## Qt 赋值方式

参考 [CommonSetting_PowerQuality_Set.cpp](https://github.com/yuchangdian/New_Jydl_Qt/blob/Unified_structure/ui_source/src/CommonSetting_PowerQuality_Set.cpp)，本次读取到的文件 Git blob 为 `03641ab7b9f2cc8a0bca0b1b07a70b2407d67d40`。

Qt 页面构造函数直接调用 `set_setting(&PowerQualitySetting)`，使用底层已有的完整 `PowerQualitySetting_struct` 为界面赋值：

- `VoltageRef_SegSwell` 设置电压暂降/暂升参考值选项。
- `RecoedSize_Normal`、`RecoedSize_Violation` 设置正常/越限录波长度，显示两位小数，单位毫秒。
- 23 个 `PQSettingUnit` 分别把 `Enable` 映射为“投入/退出”，把 `ActValue` 用 `QString::number` 格式化后填入输入框。
- 用 `QSignalBlocker` 暂时屏蔽控件信号，程序赋值不会被当成用户修改。
- `get_setting` 则反向收集界面值并计算 CRC，是既有提交功能的配套方法。

## 本项目原先的问题

本项目已有新协议 `0x1344/0x0033` 的 200 字节定值解包、C++ 快照、NAPI 读取和字段描述。但页面进入后总是发送查询，只接受比进入前更新的报文。即使底层缓存已经完整有效，界面仍要等待新回包，可能超时后保留初始值。

原 `applyPacket` 逐字段尝试赋值，也可能把不完整数据与原有内容混合。

## 本次实现

### 进入页面只读取一次

`entry/src/main/ets/pages/CommonSetting_PowerQuality_Set.ets` 的 `requestSetting`：

1. 先通过 `Jybsmr131Protocol.setting(PowerQuality)` 读取底层当前快照。
2. 如果快照完整有效，立即调用 `applyPacket` 为界面赋值，不发送查询，不启动定值轮询。
3. 缓存为空或不完整时发送一次查询，每 200 毫秒检查是否收到完整新回包，最多等待 2 秒。
4. 成功、超时或异常后立即结束等待；不周期性重查，不覆盖用户后续编辑。
5. 页面销毁时取消时钟、读取等待和原有提交确认定时器；生命周期编号阻止旧回调继续读取底层。

日期时间仍沿用页面原有时钟。提交后的原有确认流程继续按设备回包处理，属于用户提交动作，不是自动刷新。

### 完整赋值

`entry/src/main/ets/models/PowerQualityAlarmSetting.ets` 新增 `readPowerQualityAlarmSetting`：

- 检查就绪标记、公共地址、对象地址、200 字节载荷、接收版本和连接编号。
- 检查 3 个基础参数和 23 组投退/动作值，共 **49 个界面字段**。任一缺失或非有限数都不生成赋值结果，投退只接受 0/1。
- 先组织完整的显示值，再更新页面状态，避免半份赋值。
- 录波长度两位小数；动作值六位有效数字；参考值索引按 Qt 方式限制到已有选项。

`applyPacket` 保留原有 `@Observed` 行对象，通过 `@ObjectLink` 将投退和动作值传到各行控件；更新页面 `@State` 的参考值和录波长度。`applyingSetting` 对应 Qt 信号屏蔽的用途，程序赋值完成后清空修改提示。

录波频率在 Qt 的 `set_setting/get_setting` 中没有对应结构字段，现有控件继续固定只读显示 50kHz，不将其当作已从装置读取的参数。

## 界面到底层的通路

```mermaid
flowchart LR
  A[页面 requestSetting] --> B[Jybsmr131Protocol.setting]
  B --> C[NAPI getJybsmr131Packet]
  C --> D[C++ PacketStore.Get]
  D --> E[完整 200 字节定值的数值快照]
  E --> F[readPowerQualityAlarmSetting]
  F --> G[applyPacket / State / ObjectLink]
  G --> H[下拉框和动作值输入框]
```

对应代码：

- `entry/src/main/ets/protocol/Jybsmr131.ets`：公共地址 `RemoteAdjust = 0x1344`，对象地址 `PowerQuality = 0x0033`。
- `entry/src/main/cpp/napi_init.cpp`：注册 `getJybsmr131Packet`、`requestJybsmr131Packet` 和 `updateJybsmr131Setting`。
- `entry/src/main/cpp/jybsmr131_napi.cpp`：读取 C++ 快照并创建 ArkTS 对象，查询经 `TcpClient::Send` 发送。
- `entry/src/main/cpp/tcp_client.cpp`：新协议有效定值回包交给 `PacketStore::Decode`。
- `entry/src/main/cpp/protocol/jybsmr131/codec.cpp`：定值严格检查长度和 CRC，再缓存；读出时根据字段偏移转换数值。
- `entry/src/main/cpp/quality.h`：`PowerQualitySetting_struct` 包含 3 个 `uint32_t`、23 个 8 字节 `PQSettingUnit` 和 4 字节 CRC，合计 200 字节。
- `entry/src/main/cpp/protocol/jybsmr131/fields.inc`：将 49 个界面字段和 CRC 映射到结构偏移。

本次复用已有底层协议和 NAPI，修复页面读取与赋值入口，并通过新增原生协议测试验证完整字段通路。
