# TCP 2404 服务端单例与转发接口

## Qt 参考与实现范围

参考 [Qt qclient.cpp](https://github.com/yuchangdian/New_Jydl_Qt/blob/Unified_structure/core_source/client/qclient.cpp) 和 [qclient.h](https://github.com/yuchangdian/New_Jydl_Qt/blob/Unified_structure/core_source/client/qclient.h)。Qt 的 2404 服务监听所有本机地址，维护一个客户端，新连接替换旧连接；其他模块通过 `slots_Send_Data` 发送二进制数据，接收数据则交给业务解析线程。

本项目新增独立的原生 `TcpServer` 单例，提供 2404 实时字节流转发基础能力。具体定值查询响应、缓存重放等业务可以通过接收/连接回调接入；本次未自动建立“远端客户端与本机服务端之间”的业务转发。

## C++ 文件发送数据

应用已经在首页加载成功后启动服务，其他 C++ 文件可直接调用：

```cpp
#include "tcp_server.h"

bool ForwardData(const void *data, std::size_t length)
{
    return TcpServer::GetInstance().Send(data, length);
}
```

例如转发一份现有完整协议包：

```cpp
const bool queued = TcpServer::GetInstance().Send(&packet, sizeof(packet));
```

`packet` 应是业务模块已经准备好的协议报文，字段布局和长度由该业务模块负责。`Send` 按长度复制数据，支持内部包含 `0` 字节；返回后调用方可以释放或复用原缓冲区。

独立原生调用场景可手动管理生命周期：

```cpp
auto &server = TcpServer::GetInstance();
const bool listening = server.Start(); // 默认 2404，监听所有本机 IPv4 地址。
const bool connected = server.IsClientConnected();
// 退出业务时：
server.Stop();
```

## 纯 C 文件发送数据

```c
#include "tcp_server_c.h"

int forward_data(const void *data, size_t length)
{
    return tcp_server_send(data, length);
}
```

C 与 C++ 使用同一个实例。纯 C 也可调用 `tcp_server_start(TCP_SERVER_DEFAULT_PORT)`、`tcp_server_stop()`、`tcp_server_is_running()` 和 `tcp_server_is_client_connected()`。

## 接收与连接回调

- `SetReceiveHandler` 或 `tcp_server_set_receive_callback`：将收到的字节块交给后续业务模块。
- `SetConnectionHandler` 或 `tcp_server_set_connection_callback`：通知连接/断开，可在连接成功后发送业务保存的最新定值。
- 同类回调只有一个注册位置，后注册的回调替换之前的回调；设为 `nullptr` 注销。
- 回调运行在服务端 I/O 线程，调用时不持有内部锁，可安全调用 `Send`。
- TCP 是字节流，单次回调可能收到半包或多包，业务层应独立维护拼包缓存，并在连接变化时清空旧缓存。
- 数据指针只在当前回调内有效。异步处理应先复制数据，回调应快速返回。
- 回调中的 `Stop` 仅请求退出，避免线程等待自己；从业务线程再次 `Stop` 会等待线程完成。`Start` 需在业务线程调用。
- 注销不会取消已取得/正在执行的回调。释放回调捕获对象或 C `context` 前，从业务线程调用 `Stop` 并等待完成，再注销回调。
- 回调持续存在于实例中，停止后重新启动服务会继续使用已注册回调。

## 发送语义及线程行为

- `Send` 返回 `true` 表示数据已复制到发送队列，不代表对端收到或业务确认。
- 未连接、停止中、空数据、空指针、单次数据超过上限或队列已满时返回 `false`。
- 发送队列上限为 **1 MiB**，避免慢客户端无限积压内存。
- 唯一 I/O 线程操作实际 socket，处理短写、暂不可写和重试，多个业务线程可并发调用 `Send`，每次调用的数据在字节流中连续发送。
- 新客户端替换旧客户端时清空旧发送队列，避免旧连接的数据进入新连接。
- 非阻塞 socket 配合最多 100 毫秒的 `poll` 等待，正常无阻塞回调时可及时停止。大流量收发按单轮预算处理，避免线程饥饿。
- `Start`/`Stop` 通过生命周期锁串行化；相同配置重复启动成功，不同配置需先停止。退出会回收监听及客户端 socket，支持再次启动。
- OpenHarmony 使用 POSIX socket；`_WIN32` 分支只为在本机 Windows 上测试同一套服务逻辑。

## ArkTS 生命周期和日志

NAPI 导出 `startTcpServer(port?)`、`stopTcpServer()`、`isTcpServerRunning()`、`isTcpServerClientConnected()`。ArkTS 端监听端口仅接受 1～65535 的整数，默认 2404。

`EntryAbility` 在首页加载成功后分别启动已有客户端和新增服务端；窗口或应用销毁时分别停止。服务端启动失败会记录错误，不阻止已有客户端流程。

新服务端日志标签为 `JY_TCP_SERVER`，根目录 `看TCP日志.ps1` 已加入该标签。
