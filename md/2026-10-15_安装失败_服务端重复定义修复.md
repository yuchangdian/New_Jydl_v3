# 安装前构建失败：TCP 服务端重复定义

## 原因

用户提供的日志失败在 `:entry:default@BuildNativeWithNinja`。链接 `libentry.so` 时出现 `ld.lld: error: duplicate symbol`，尚未执行设备安装。

`entry/src/main/cpp/tcp_client.cpp` 原第 15 行写了：

```cpp
#include "tcp_server.cpp"
```

`#include` 会把被包含文件的内容直接展开到当前编译单元。因此 TCP 服务端的函数实现进入了 `tcp_client.cpp.o`。同时，`CMakeLists.txt` 已单独列出 `tcp_server.cpp`，相同实现又被编译到 `tcp_server.cpp.o`，最终链接时发生重复定义。

## 修复

将实现文件包含改为头文件包含，放到文件顶部：

```cpp
#include "tcp_server_c.h"
```

当前业务代码调用的是 `tcp_server_send(...)`，其声明在 `tcp_server_c.h`，C++ 文件也可以使用这个 C 接口。保留现有转发调用以及 CMake 中的 `tcp_server.cpp`，由 CMake 单独编译一次实现。

后续其他文件需要调用服务端时：C 风格函数包含 `tcp_server_c.h`；使用 `TcpServer::GetInstance()` 等 C++ 接口包含 `tcp_server.h`。调用方不需要包含 `.cpp` 文件。

## 验证结果

- 执行默认产品、entry 模块、debug 模式的 `assembleHap --no-daemon`。
- 原生编译链接、ArkTS 编译、HAP 打包及签名均通过，输出 `BUILD SUCCESSFUL in 36 s 204 ms`。
- 已生成安装包：`entry/build/default/outputs/default/entry-default-signed.hap`。
- 完整构建日志：`md/2026-10-15_安装失败修复构建.log`。
- 构建中仍有现有 API 弃用等警告，不影响此次打包成功。
- `hdc list targets` 未返回设备，未进行实际设备安装验证。连接设备后可在 DevEco Studio 中重新点击 Run。
